# BUG-001. 갱신가입 시 차량 부속정보 중복으로 다음 단계 진행 불가

## Summary

갱신가입 과정에서 기존 입력 할인부속과 외부조회된 동일 할인부속이 중복된 상태로 남아, `부속정보를 확인해 주세요` 팝업이 반복 표시되고 보험료 계산 단계로 진행되지 않는 오류

## Environment

- 오류 확인 환경: 테스트계
- 수정 후 확인 환경: 테스트계·운영계
- 확인 채널: PC·모바일
- 연계 확인: 기간계·모니터링 로그
- 테스트 유형: 기능 검증·재검증·회귀검증
- 서비스 영역: 자동차보험 갱신가입·자동차정보

## Precondition

- 자동차보험 갱신가입이 가능한 계약이 존재한다.
- 기존 계약에 고객이 직접 입력한 할인부속 A가 존재한다.
- 외부 차량정보 조회 결과에도 동일한 할인부속 A가 존재한다.
- 중복정보 조정 팝업에서 부속정보를 확인하고 조정할 수 있다.

## Steps to Reproduce

1. 기존 입력 할인부속 A가 존재하는 계약으로 갱신가입을 시작한다.
2. 자동차정보 화면에서 기존 할인부속 A가 조회되는지 확인한다.
3. 외부 차량정보 조회를 실행한다.
4. 외부조회 결과에도 동일한 할인부속 A가 존재하는지 확인한다.
5. 중복정보 조정 팝업에서 부속명·최초가액·현재가액·부속 여부를 확인한다.
6. 중복정보를 조정하고 확인한다.
7. 다음 단계를 선택한다.
8. `부속정보를 확인해 주세요` 팝업이 표시되는지 확인한다.
9. 팝업을 확인한 후 다시 다음 단계를 선택한다.
10. 동일한 팝업이 반복 표시되고 보험료 계산 단계로 진행되지 않는지 확인한다.

## Expected Result

- 외부조회된 할인부속 정보를 우선 적용한다.
- 동일한 할인부속은 하나만 유지한다.
- 외부조회된 할인부속은 고객이 임의로 제거할 수 없도록 처리한다.
- 기타부속은 고객이 선택을 해제하거나 가액을 수정할 수 있다.
- 중복정보 조정 후 안내 팝업이 반복되지 않아야 한다.
- 보험료 계산 단계로 정상적으로 이동해야 한다.

## Actual Result

- 중복정보를 조정한 후에도 동일한 부속정보가 정상적으로 정리되지 않았다.
- 다음 단계를 선택하면 `부속정보를 확인해 주세요` 팝업이 표시됐다.
- 팝업을 확인한 후 다시 진행해도 동일한 팝업이 반복 표시됐다.
- 보험료 계산 단계로 진입할 수 없었다.

## 발견 및 전달

테스트 요청을 검증하는 과정에서 오류를 확인했다.

테스트계의 PC와 모바일에서 동일한 조건을 확인하고, 확인 결과를 Redmine과 메신저로 개발·현업 담당자에게 전달했다.

구체적인 개발 원인과 내부 수정 과정은 직접 확인하지 못했다.

## Severity

`Major`

### Reason

차량 부속정보 중복으로 인해 자동차보험 갱신가입의 보험료 계산 단계에 진입할 수 없었다. 갱신가입의 주요 흐름이 중단되는 오류이므로 `Major`로 판단했다.

## Priority

`High`

### Reason

동일한 부속정보가 존재하는 갱신계약에서 가입 진행이 반복적으로 차단됐다. 보험료 계산 이전에 주요 흐름이 중단되므로 우선 확인이 필요한 오류로 판단했다.

> `Severity`와 `Priority`는 공개 포트폴리오 작성 기준으로 재구성한 판단이며 실제 사내 분류값을 의미하지 않는다.

## Customer Impact

- 고객이 갱신보험료 계산 단계로 진행할 수 없다.
- 갱신보험료를 확인할 수 없다.
- 중복 상태가 해소되지 않으면 온라인 갱신가입을 완료할 수 없다.

## 수정 후 재검증

수정사항이 테스트계에 반영된 후 최초 오류조건을 다시 확인했다.

### 최초 오류조건 재검증

- 외부조회 할인부속 우선 적용
- 동일 할인부속 하나만 유지
- 외부조회 할인부속 제거 제한
- `부속정보를 확인해 주세요` 팝업 반복 미발생
- 보험료 계산 단계 정상 진입
- 보험료 정상 계산

### 회귀검증

- 기타부속 선택 해제 및 가액 수정
- 청약내용 확인
- 결제 및 가입 완료
- 기간계 최종 부속정보와 보험료 확인
- 모니터링 로그에서 부속정보 중복 미발생 확인
- 운영 이관 후 PC·모바일 가입 흐름 재확인

## 확인 한계

- 실제 API 요청·응답과 데이터베이스는 직접 확인하지 않았다.
- 부속정보가 중복된 개발 원인은 전달받지 못했다.
- 화면, 기간계 및 모니터링 로그에서 직접 확인한 결과만 작성했다.

## QA Note

이 사례는 기존 계약정보와 외부조회 정보가 함께 사용될 때 동일한 부속정보가 하나의 유효한 정보로 정리되는지를 확인한 사례다.
