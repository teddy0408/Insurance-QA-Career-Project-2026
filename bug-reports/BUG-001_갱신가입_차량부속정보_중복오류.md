# BUG-001. 갱신가입 시 차량 부속정보 중복으로 보험료 계산 단계 진행 불가

## 확인 환경 및 범위

| 항목 | 내용 |
| --- | --- |
| 확인 경위 | 테스트 요청 검증 중 직접 발견 |
| 오류 재현 환경·채널 | 테스트계 / PC 웹·모바일 웹·모바일 앱 |
| 수정 후 확인 환경·채널 | 테스트계·운영계 / PC 웹·모바일 웹·모바일 앱 |
| 연계 확인 | 기간계·모니터링 로그 |
| 대상 업무 | 자동차보험 갱신가입·자동차정보 |
| 공유 방식 | Redmine·메신저를 통해 발생 조건과 영향 범위를 개발 담당자·관련 업무 담당자에게 공유 |

## 사전조건

- 자동차보험 갱신가입이 가능한 계약이 존재한다.
- 기존 계약에 고객이 직접 입력한 할인부속 A가 존재한다.
- 외부 차량정보 조회 결과에도 동일한 할인부속 A가 존재한다.

## 재현 절차

1. 기존 입력 할인부속 A가 존재하는 계약으로 갱신가입을 시작한다.
2. 자동차정보 화면에서 외부 차량정보를 조회하고, 동일한 할인부속 A가 조회되는지 확인한다.
3. 이어서 표시되는 기존 입력 부속 선택 화면에서 기존 할인부속 A를 제외하고 외부 조회 할인부속만 유지한다.
4. 다음으로 표시되는 총차량가액을 확인한다.
5. 다음 단계를 선택하고, 안내 팝업을 닫은 뒤 다시 진행을 시도한다.

## 기대 결과

- 외부 조회 할인부속을 기준으로 동일 할인부속이 하나만 유지돼야 한다.
- 중복 정보 조정 결과와 총차량가액이 정상 반영돼 안내가 반복되지 않고 보험료 계산 단계로 진행돼야 한다.

## 실제 결과

- 기존 입력 할인부속을 제외하고 외부 조회 할인부속만 유지하도록 조정했으나, 이후 표시된 총차량가액이 상승한 것을 확인했다.
- 다음 단계 선택 시 `부속정보를 확인해 주세요` 팝업이 반복돼 보험료 계산 단계로 진행할 수 없었다.
- 차량모델을 다시 선택하면 보험료 계산 단계까지 진행할 수 있었다.

## 결함 등급

| 구분 | 판단 | 근거 |
| --- | --- | --- |
| Severity | `Major` | 동일 할인부속이 중복된 갱신계약에서 보험료 계산 단계로 진입할 수 없어 가입 흐름이 중단됨 |
| Priority | `High` | 테스트계의 PC 웹·모바일 웹·모바일 앱에서 재현됐으며 운영 이관 전 수정과 회귀검증이 필요함 |

> 결함 등급은 공개 포트폴리오 작성 기준으로 재구성한 판단이며 실제 사내 분류값을 의미하지 않는다.

## 잠재 고객 영향

- 동일 조건이 운영환경에서 발생하면 고객이 갱신보험료를 확인하거나 온라인 갱신가입을 완료하는 데 어려움을 겪을 수 있다.
- 차량모델을 다시 선택하는 우회 방법을 알지 못하면 안내 팝업 반복으로 가입을 중단할 수 있다.
- 총차량가액 상승이 보험료 계산에 영향을 줄 가능성이 있으나, 오류 발생 당시 보험료 계산 결과 화면에는 진입하지 못해 실제 보험료 상승 여부는 확인하지 못했다.

## 수정 후 확인 결과

| 구분 | 확인 환경 | 확인 결과 |
| --- | --- | --- |
| 수정 후 재검증 | 테스트계 | 외부 조회 할인부속을 우선 적용하고 동일 할인부속이 하나만 유지되는지 확인했다. 외부 조회 할인부속 제거 제한, 안내 팝업 반복 미발생, 보험료 계산 단계 정상 진입과 보험료 계산을 확인했다. |
| 회귀검증 | 테스트계 | 기타부속 선택 해제와 가액 수정, 청약내용, 결제·가입 완료를 확인했다. 기간계에서는 최종 부속정보와 보험료를 확인하고, 모니터링 로그에서는 부속정보 중복이 발생하지 않았는지 확인했다. |
| 운영 이관 후 확인 | 운영계 | PC 웹·모바일 웹·모바일 앱에서 동일 할인부속 중복 조건을 다시 확인했다. 외부 조회 할인부속 하나만 유지되고 안내 팝업이 반복되지 않으며 보험료 계산 단계에 정상 진입하는지 확인했다. 운영계 결제·가입 완료는 확인 범위에 포함하지 않았다. |

## 확인 한계

- 오류 발생 당시 보험료 계산 결과 화면에는 진입하지 못해 중복 부속정보로 인한 실제 보험료 상승 여부는 확인하지 못했다.
- 이 결함으로 실제 고객의 결제·계약 피해가 발생했는지는 확인하지 않았다.
- 개발 코드상의 원인과 DB 저장값은 직접 확인하지 않았다.
- 운영계에서는 수정 반영 후 보험료 계산 단계 진입까지 확인했으며, 결제·가입 완료는 확인하지 않았다.

## QA 판단

팝업이 반복되지 않는지만으로 수정 완료를 판단하지 않았다. 부속정보는 총차량가액·보험료·청약정보에 연결되므로, 테스트계에서 동일 부속의 중복 해소와 함께 기타부속 수정, 보험료 계산, 청약·결제·가입 완료 및 기간계 최종 정보를 회귀검증했다.
