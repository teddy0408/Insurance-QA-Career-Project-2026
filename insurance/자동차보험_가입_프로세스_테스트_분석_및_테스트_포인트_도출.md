# 자동차보험 가입·계약변경 품질 리스크 분석 및 테스트 전략

## 1. 문서 목적

본 문서는 자동차보험 가입·갱신·계약변경 흐름을 기준으로 주요 업무 규칙과 품질 위험을 분석하고, 검증 범위와 확인 기준을 정리한다.

보험 상담·서비스 변경 검증·운영 이슈 확인 경험을 기반으로 공개 가능한 범위에서 일반화했으며, 직접 확인한 결제 예외·복구 사례와 경계·오류 사례는 별도 항목으로 구분했다.

### ID 구분

> 이 문서의 `RISK-*`는 품질 위험 식별용이며, `test-cases` 폴더의 테스트케이스 ID와 일대일로 대응하지 않는다. 표에는 상세 사례와 연결되거나 보험료·계약·배서 상태에 영향을 주는 대표 위험만 선별했다.

## 2. 분석 영역과 공통 검증 원칙

### 2.1 분석 영역과 우선 검증 위험

| 분석 영역 | 주요 검증 대상 | 우선 검증 위험 |
| --- | --- | --- |
| 자동차 정보 | 차량 조회·보험 기간·외부 조회·부속 정보·차량가액 | 외부 조회 정보와 기존 입력 정보의 중복, 이전 차량 정보 잔존, 일부 조회 정보 삭제 |
| 운전자 범위와 할인 특약 | 운전자 범위·관계·연령 조건·할인 특약 | 숨겨진 이전 정보 사용, 가입할 수 없는 특약 유지, 보험료 재계산 누락 |
| 보험료 계산 결과 | 담보·가입금액·할인 특약·최종 보험료·채널별 결과 | 변경 전 보험료 잔존, 할인율 오적용, 청약·결제·기간계 금액 불일치 |
| 계약 정보·청약 확인 | 계약자·피보험자·질권·사진·최종 청약 내용 | 이전 단계 정보 불일치, 필수 증빙 누락, 최종 계약 조건 불일치 |
| 보험료 결제와 계약 생성 | 인증·결제 승인·청약 상태·계약 생성·증권·완료 안내 | 결제 승인 후 계약 미생성, 중복 승인·중복 계약, 미완료 계약의 가입 완료 표시 |
| 안전운전 할인특약 계약변경 | 외부 점수·적용 할인율·환급보험료·배서·완료 안내 | 적용 기준일·할인율·환급보험료·배서 상태 불일치 |

가입자 확인과 가입 완료는 인증·동의·최종 처리 상태를 확인하는 공통 검증 영역으로 두고, 상세 분석은 위 6개 영역을 중심으로 구성했다.

### 2.2 공통 검증 원칙

- 이전 단계로 돌아갔을 때 입력한 유효 정보가 유지되는지 확인한다.
- 계약변경 후 갱신할 때 변경 대상이 아닌 기존 유효 정보가 유지되는지 확인한다.
- 현재 선택값과 화면에서 숨겨진 이전값을 구분한다.
- 변경된 값이 보험료·청약·결제·계약 단계에 일관되게 반영되는지 확인한다.
- 조회 결과 없음, 항목별 조회 성공·실패와 전체 조회 실패를 구분하고, 재시도 시 이전 유효 정보 유지 여부를 확인한다.
- 화면 안내만으로 완료를 판단하지 않고 사례별 확인 범위에서 결제·계약·배서·증권·안내 상태를 확인한다.
- 특약 신청 기간이 기존 가입 기간과 겹치거나 자동차보험 계약의 효력 범위를 벗어나지 않는지 확인한다.

### 2.3 검증 범위 선정과 확인 완료 기준

| 구분 | 기준 |
| --- | --- |
| 우선 검증 | 보험료·결제·계약·배서 상태에 영향을 주는 조건을 먼저 확인 |
| 범위 확장 | 화면 오류가 다음 단계의 금액·계약정보에 영향을 줄 수 있으면 청약·결제·기간계까지 확인 |
| 계약 조건 | 신규·갱신·계약변경과 적용 개시일 전후 조건을 구분 |
| 채널 범위 | PC 웹·모바일 웹·모바일 앱 중 변경 영향이 있는 채널과 기간계 상태를 선정 |
| 확인 완료 | 최초 오류 조건의 차단 여부와 영향받는 정상 흐름을 확인하고, 직접 확인한 채널과 기간계의 최종 상태를 대조 |
| 미확인 범위 | 운영계에서 직접 수행하지 않은 결제·계약변경과 그 밖의 미확인 결과를 별도로 기록 |

## 3. 자동차 정보

### 3.1 차량·보험기간

- 차량 식별정보를 변경한 경우 이전 조회결과와 부속정보가 현재 차량에 남지 않는지 확인한다.
- 보험기간을 변경한 경우 적용 개시일·할인특약·보험료가 변경 조건을 기준으로 다시 계산되는지 확인한다.

### 3.2 차량 상세정보와 외부 조회

| ID | 상태 변경 | 기대 결과 | 주요 위험 |
| --- | --- | --- | --- |
| RISK-VEH-01 | 기존 차량 정보가 있는 상태에서 외부 조회 | 동일 부속의 중복을 제거하고 하나의 유효 정보로 병합 | 같은 부속이 두 번 반영됨 |
| RISK-VEH-02 | 세부차종 변경 후 재조회 | 변경 차량 기준으로 차량가액 재계산 | 이전 차량 부속·가액 잔존 |
| RISK-VEH-03 | 할인부속 조회 및 기타부속 입력 | 외부 조회 할인부속의 제거 제한과 기타부속의 선택 해제·가액 수정 기준 적용 | 정보 유형별 수정 기준 오적용 또는 부속가액 이중 합산 |
| RISK-VEH-04 | 조회 결과 없음 또는 실패 | 상태에 맞는 대체 입력·재조회 흐름 제공 | 조회 상태 오인 또는 대체 입력 단계 누락 |
| RISK-VEH-05 | 여러 조회 항목 중 일부만 성공 | 성공한 조회 정보는 유지하고 실패 항목은 미조회 상태로 구분 | 실패한 항목 때문에 성공한 조회 정보까지 삭제됨 |

차량 정보 검증은 팝업 표시 여부에 그치지 않고, 영향 범위에 따라 최종 부속 정보·총차량가액·보험료·청약 내용과 기간계 계약 정보까지 확인한다.

`RISK-VEH-01`의 실제 오류 조건은 [VEH-002. 차량부속정보 중복 처리](../test-cases/VEH-002_차량부속정보_중복처리.md)와 [BUG-001. 갱신가입 시 차량 부속정보 중복으로 보험료 계산 단계 진행 불가](../bug-reports/BUG-001_갱신가입_차량부속정보_중복오류.md)에서 확인할 수 있다. `RISK-VEH-03`은 `VEH-002`의 회귀검증 범위로, `RISK-VEH-04`는 [EVD-001. 외부 주행거리 조회 실패 후 사진형 전환](../test-cases/EVD-001_외부주행거리_조회실패_사진형전환.md)의 대체 흐름과 연결된다.

## 7. 보험료 결제와 계약 생성

### 7.1 처리 흐름

| 결제 유형 | 대표 수단 | 처리 흐름 |
| --- | --- | --- |
| 즉시 승인형 | 신용카드·실시간 계좌이체 | 결제 요청 → 인증 → 승인 결과 확인 → 계약 생성 → 가입 완료 |
| 외부 연계형 | 간편결제 | 결제 요청 → 인증 → 외부 결제 화면 → 보험사 화면 복귀 → 결과 확인 → 계약 생성 → 가입 완료 |
| 후속 입금형 | 무통장입금 | 가상계좌 발급 → 입금 전 청약상태 → 입금 확인 → 계약 생성 → 가입 완료·증권 발송 |

### 7.2 상태 정합성

결제 성공 여부만 확인하지 않고 보험료 계산 결과, 청약내용, 승인상태, 계약 생성, 증권과 가입 완료 안내가 같은 최종 상태를 나타내는지 확인한다.

| ID | 검증 항목 | 기대 결과 |
| --- | --- | --- |
| RISK-PAY-01 | 단계별 최종 보험료 | 계산 결과·청약·결제·기간계 금액 일치 |
| RISK-PAY-02 | 간편결제 후 화면 복귀 | 결제 결과와 계약 생성 상태를 확인한 후 가입 완료 화면으로 이동 |
| RISK-PAY-03 | 결제 승인 후 계약 미생성 | 결제·청약·계약 상태를 구분하고 계약 미생성 상태는 가입 완료로 처리하지 않음 |
| RISK-PAY-04 | 무통장입금 | 입금 전후 청약·계약 상태 정상 변경 |
| RISK-PAY-05 | 완료 후 발송 | 알림과 증권이 조건에 맞게 발송 |

동일 청약·동일 결제에 대한 반복 요청은 중복 승인과 중복 계약을 생성하지 않아야 한다. 별도 청약 또는 연속 계약의 허용 여부는 상품·채널의 업무정책을 확인해 판단한다.

## 8. 안전운전 할인특약 계약변경

### 8.1 목적과 처리 흐름

보험 기간 중 외부 안전운전 점수가 변경된 경우 조회 점수, 적용 할인율, 환급보험료와 배서 상태가 일치하는지 검증한다.

> 계약 선택 → 변경기준일 확인 → 정보 제공 동의·점수 재조회 → 가입 가능 여부 → 변경점수·환급보험료 확인 → 변경 신청·환급정보 입력 → 본인인증 → 배서·환급 → 결과 안내

| 환경 | 점수 처리 | 검증 범위 |
| --- | --- | --- |
| 테스트계 | 점수를 수기로 반영 | 점수 구간·할인율·환급보험료·배서 |
| 운영계 | 외부 서비스에서 자동 재조회 | 조회 결과·적용 기준일·계약·환급·안내 |

### 8.2 핵심 위험

| ID | 검증 항목 | 기대 결과 |
| --- | --- | --- |
| RISK-UBI-01 | 특약 시행일 경계 | 보험 개시일 기준 할인율 적용 |
| RISK-UBI-02 | 채널별 환급금 | 확인한 채널과 기간계의 환급보험료 일치 |
| RISK-UBI-03 | 상호 배타 특약 | 요구사항에서 정한 시점에 가입 불가 안내 |

| RISK-UBI-05 | 완료 안내 | 알림톡·문자·이메일 발송 |

### 8.3 확인한 경계·오류 사례

다음은 안전운전 할인특약 계약변경 과정에서 직접 확인한 사례다.

| 관련 위험 | 사례 | 조건·업무 규칙 | 실제 결과 | 수정 후 재검증 |
| --- | --- | --- | --- | --- |
| `RISK-UBI-01` | 특약 시행일 경계 | 할인율 시행일을 `T`로 두고 보험 개시일 `T-1`·`T+1` 조건 비교 | `T+1` 계약에도 기존 할인율이 적용돼 환급보험료가 변경되지 않음 | 시행일 전후 할인율과 환급보험료 확인 |
| `RISK-UBI-02` | 채널별 환급보험료 불일치 | 동일 계약·변경 기준일의 채널·기간계 환급보험료 비교 | 변경 기준일에 따른 할인율이 잘못 적용돼 환급보험료 불일치 | 확인한 채널과 기간계의 환급보험료 일치 확인 |
| `RISK-UBI-03` | 상호 배타 특약 안내 시점 | 배서 종류 선택 시 가입 불가 안내가 표시돼야 함 | 점수 조회 이후에 안내가 표시됨 | 배서 종류 선택 시점에 안내되는지 테스트계·운영계 확인 |
| `RISK-UBI-04` | 동일 할인구간의 0원 배서 | 점수는 상승했지만 할인구간과 환급보험료는 변경되지 않음 | 환급보험료 0원인 변경 배서가 생성됨 | 업무 규칙 보완 후 0원 배서 미생성 확인 |
| `RISK-UBI-05` | 변경 완료 이메일 미발송 | 배서·환급 완료 후 결과 안내가 발송돼야 함 | 배서와 환급은 완료됐지만 이메일이 발송되지 않음 | 배서 완료 상태와 이메일 수신 여부 확인 |

동일 할인구간의 0원 배서 사례는 기존 요구사항 위반이 아니라, 테스트 과정에서 누락된 업무기준을 확인하고 보완한 사례로 구분한다.

### 8.4 회귀검증 범위

안전운전 할인특약 계약변경이 기존 가입 흐름에 영향을 줄 수 있는 경우, 수정 범위와 확인 환경에 따라 다음 항목에서 회귀 대상을 선정한다.

1. 보험료 계산
2. 계약정보와 청약내용 확인
3. 보험료 결제
4. 계약 생성
5. 가입 완료
6. 완료 안내 발송

#### 롤백 반영 후 확인

운영 반영 후 관련 업무 담당자의 결정으로 롤백된 사례에서는 롤백 반영 결과와 보험료 계산·결제·가입 완료 흐름을 다시 확인했다. 롤백 여부는 관련 업무 담당자가 결정했다.
