# END-001. 단기운전자 확대특약 가입 기간 유효성

## 개요

| 항목 | 내용 |
| --- | --- |
| 확인 경위 | 챗봇 단기운전자 확대특약 가입 기능 신설 테스트 중 오류 확인 |
| 검증 목적 | 기존 특약 가입 기간 중복, 자동차보험 계약 개시일 경계와 이용 기간 최소·최대 조건의 신청 제어 확인 |
| 대상 흐름 | 가입 챗봇 진입 → 차량번호 입력 → 이용 시작일자 입력 → 이용 기간 입력 → 보험료 계산 → 결제 |
| 검증 관점 | 기간 유효성·경계 조건 |
| 확인 환경·채널 | 테스트계·운영계 / 모바일 웹·모바일 앱 |
| 공유 방식 | 팀 단체 채팅방 |

## 사전조건

### 조건 A. 기존 특약과 기간이 겹치는 신청

- 대상 자동차보험 계약이 유효한 상태다.
- 동일 계약에 단기운전자 확대특약이 이미 가입돼 있다.
- 기존 특약은 결제가 완료되고 효력이 발생한 상태다.
- 기존 특약기간은 `T ~ T+4`다.

### 조건 B. 자동차보험 계약 개시일 경계의 신청

- 자동차보험 계약 개시일은 `P`다.
- 테스트 시점에는 자동차보험 계약의 효력이 아직 개시되지 않은 상태다.
- 해당 계약에는 차량번호가 등록돼 있으며 모바일에서 정상 조회할 수 있다.
- 신청 시작일은 계약 개시일 전날 `P-1`, 개시일 당일 `P`, 개시일 다음날 `P+1` 조건으로 구분한다.

### 조건 C. 이용 기간 최소·최대 경계

- 신청 가능한 정상 시작일을 선택한다.
- 이용 기간은 최소 1일, 최대 28일이다.
- 이용 기간은 1일·28일·29일로 구분해 확인한다.

> `T`와 `P`는 실제 계약을 식별하지 않도록 일반화한 기준일이다.

## 테스트 절차 및 기대 결과

### 조건 A. 기존 특약과 기간이 겹치는 신청

| 단계 | 테스트 절차 | 기대 결과 |
| --- | --- | --- |
| 1 | 모바일 웹 또는 모바일 앱에서 가입 챗봇에 진입하고 기존 특약이 가입된 계약의 차량번호를 입력한다. | 이용 시작일자 입력 단계로 진행된다. |
| 2 | 기존 특약기간 `T ~ T+4`와 겹치는 `T+2 ~ T+4`를 입력한다. | 기간 중복 안내와 함께 신청이 차단된다. |
| 3 | 기존 특약기간과 겹치지 않는 `T+5 ~ T+7`을 입력한다. | 보험료가 계산되고 결제 단계로 진행된다. |

### 조건 B. 자동차보험 계약 개시일 경계의 신청

| 단계 | 테스트 절차 | 기대 결과 |
| --- | --- | --- |
| 1 | 모바일 웹 또는 모바일 앱에서 단기운전자 확대특약 가입 챗봇에 진입한다. | 차량번호 입력 단계가 표시된다. |
| 2 | 아직 개시되지 않은 계약의 차량번호를 입력한다. | 이용 시작일자 입력 단계로 진행된다. |
| 3 | 계약 개시일 전날인 `P-1`을 신청 시작일로 입력한다. | 신청 시작일 재입력 안내와 함께 진행이 차단된다. |
| 4 | 계약 개시일 당일인 `P`를 신청 시작일로 입력한다. | 신청 시작일 재입력 안내와 함께 진행이 차단된다. |
| 5 | 계약 개시일 다음날인 `P+1`을 신청 시작일로 입력한다. | 정상적으로 보험료가 계산된다. |

### 조건 C. 이용 기간 최소·최대 경계

| 단계 | 테스트 절차 | 기대 결과 |
| --- | --- | --- |
| 1 | 정상적으로 신청 가능한 시작일을 선택하고 이용 기간을 1일로 입력한다. | 입력값이 수용되고 다음 단계로 진행된다. |
| 2 | 이용 기간을 28일로 입력한다. | 입력값이 수용되고 다음 단계로 진행된다. |
| 3 | 이용 기간을 29일로 입력한다. | 이용 기간 재입력 안내와 함께 진행이 차단된다. |

## 실제 결과

### 조건 A. 기존 특약과 기간이 겹치는 신청

- 기존 배서내역에 `T ~ T+4`의 특약 가입 기간이 표시됐다.
- 기존 특약 기간과 일부 겹치는 `T+2 ~ T+4`를 입력했지만 신청이 차단되지 않았고, 테스트계에서 배서계약이 생성됐다.
- 추가로 완전히 겹치는 조건, 하루만 겹치는 조건과 서로 인접하지만 겹치지 않는 조건을 구분해 신청 차단 여부를 비교했다.

### 조건 B. 자동차보험 계약 개시일 경계의 신청

- 계약 개시일 전날인 `P-1`, 개시일 당일인 `P`, 개시일 다음날인 `P+1`을 모두 신청 시작일로 입력할 수 있어 가입 절차가 진행되는 오류를 확인했다.
- 정상 기준에서는 `P-1`과 `P`가 차단되고 `P+1`부터 신청할 수 있어야 했다.
- `P-1` 조건에서는 테스트계에서 결제와 배서계약 생성까지 확인했다.

### 조건 C. 이용 기간 최소·최대 경계

- 이용 기간 1일과 28일은 정상적으로 입력할 수 있었다.
- 29일을 입력하면 이용 기간을 다시 입력하라는 안내가 표시되고 진행이 차단됐다.

조건 A는 테스트 요청에 포함된 조건이고, 조건 B는 가입 기간 검증 과정에서 추가로 확인한 계약 개시일 경계 조건이다. 조건 C는 이용 기간 최소·최대 기준의 정상 제어를 확인한 조건이다. 세 조건 모두 모바일 웹·모바일 앱에서 확인했으며 PC 웹에서는 동일 조건을 확인하지 않았다.

## QA 판단

테스트 요청에 포함된 기간 중복 조건을 확인하고, 자동차보험 계약 개시일 경계와 이용 기간 최소·최대 조건까지 구분해 검증했다. 비정상 조건의 신청 차단과 정상 조건의 보험료 계산·결제 흐름을 구분해 확인했다.
