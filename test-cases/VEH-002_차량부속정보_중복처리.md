# VEH-002. 외부 차량정보 조회 시 기존 입력 부속의 중복 처리

## 개요

| 항목 | 내용 |
| --- | --- |
| 확인 경위 | 테스트 요청 검증 중 오류 확인 |
| 검증 목적 | 기존 입력 부속과 외부 조회 부속의 중복 처리 및 후속 정보 정합성 확인 |
| 대상 흐름 | 갱신계약 자동차정보 조회 → 중복 부속 조정 → 총차량가액 확정 → 보험료 계산 → 청약내용 확인 → 결제·가입 완료 |
| 검증 관점 | 데이터 병합·데이터 정합성 |
| 확인 환경·채널 | 테스트계·운영계 / PC 웹·모바일 |
| 공유 방식 | Redmine·메신저 |

## 사전조건

- 갱신계약에 고객이 직접 입력한 할인부속 A가 존재한다.
- 외부 차량정보 조회 결과에도 동일한 할인부속 A가 존재한다.
- 선택 해제와 가액 수정 여부를 확인할 기타부속이 존재한다.

## 테스트 절차 및 기대 결과

| 단계 | 테스트 절차 | 기대 결과 |
| --- | --- | --- |
| 1 | 갱신계약의 자동차정보 화면에 진입한다. | 전년도 부속정보가 정상적으로 조회된다. |
| 2 | 외부 차량정보를 조회한다. | 동일한 외부 조회 부속과 기존 입력 부속이 중복정보 조정 대상으로 표시된다. |
| 3 | 외부 조회 할인부속과 기타부속의 선택·수정 가능 여부를 확인한다. | 외부 조회 할인부속은 제거할 수 없고, 기타부속은 선택 해제와 가액 수정이 가능하다. |
| 4 | 중복정보를 조정하고 총차량가액을 확정한다. | 동일 할인부속이 하나만 유지되고 조정된 부속정보를 반영한 총차량가액이 확정된다. |
| 5 | 보험료를 계산하고 청약내용 확인부터 결제·가입 완료까지 진행한다. | 최종 부속정보와 보험료가 청약내용에 반영된 상태로 가입이 완료된다. |
| 6 | 기간계 계약정보와 모니터링 로그를 확인한다. | 기간계의 최종 부속정보·보험료가 화면 결과와 일치하고, 모니터링 로그에서 동일 부속의 중복 반영이 확인되지 않는다. |

## 실제 결과

기존 입력 할인부속을 제외하고 외부 조회 할인부속만 유지한 뒤 다음 단계를 선택했으나, `부속정보를 확인해 주세요` 팝업이 반복 표시됐고 보험료 계산 단계로 진행할 수 없었다.

`VEH-002`와 `BUG-001`은 동일한 사례다. 오류 재현과 업무 영향은 [BUG-001. 갱신가입 시 차량 부속정보 중복으로 보험료 계산 단계 진행 불가](../bug-reports/BUG-001_갱신가입_차량부속정보_중복오류.md)에서 더 상세히 정리했다.

## 수정 후 확인

| 구분 | 확인 환경 | 확인 결과 |
| --- | --- | --- |
| 수정 후 재검증 | 테스트계 | 동일 할인부속 하나만 유지, 외부 조회 할인부속 제거 제한, 안내 팝업 반복 미발생, 총차량가액 확정과 보험료 계산 정상 진행을 확인했다. 모니터링 로그에서는 부속정보 중복이 발생하지 않았는지 확인했다. |
| 회귀검증 | 테스트계 | 기타부속 선택 해제·가액 수정, 청약내용, 결제·가입 완료를 확인했다. 기간계에서는 최종 부속정보와 보험료를 확인했다. |
| 운영 이관 후 확인 | 운영계 | PC 웹·모바일에서 동일한 중복 조건을 재확인했다. 외부 조회 할인부속 하나만 유지, 안내 팝업 반복 미발생과 보험료 계산 단계 진입을 확인했다. 운영계 결제·가입 완료는 확인하지 않았다. |

## QA 판단

중복 해소 조건과 회귀 조건을 구분했다. 오류 조건에서는 동일 부속의 단일 반영과 총차량가액 확정을, 회귀 조건에서는 외부 조회 할인부속의 제거 제한과 기타부속의 선택 해제·가액 수정을 확인했다.
