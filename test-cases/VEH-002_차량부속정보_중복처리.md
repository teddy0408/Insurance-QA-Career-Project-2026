# VEH-002. 외부 차량정보 조회 시 기존 입력 부속의 중복 처리

## 개요

| 항목 | 내용 |
| --- | --- |
| 확인 경위 | 테스트 요청 검증 중 오류 확인 |
| 검증 목적 | 기존 입력 부속과 외부 조회 부속의 중복 처리 및 후속 정보 정합성 확인 |
| 대상 흐름 | 테스트계: 갱신계약 자동차정보 조회 → 중복 부속 조정 → 총차량가액 확정 → 보험료 계산 → 청약내용 확인 → 결제·가입 완료 / 운영계: 수정 반영 후 보험료 계산 단계 진입까지 확인 |
| 검증 관점 | 데이터 병합·데이터 정합성 |
| 확인 환경·채널 | 테스트계·운영계 / PC 웹·모바일 웹·모바일 앱 |
| 공유 방식 | Redmine·메신저 |

## 사전조건

- 갱신계약에 고객이 직접 입력한 할인부속 A가 존재한다.
- 외부 차량정보 조회 결과에도 동일한 할인부속 A가 존재한다.
- 선택 해제와 가액 수정 여부를 확인할 기타부속이 존재한다.

## 테스트 절차 및 기대 결과

이 테스트케이스는 퇴사 후 실제 검증 경험과 기억을 바탕으로 재구성했다. 당시에는 테스트 제목·확인 조건·회귀 항목을 개인 메모로 정리해 사용했으며, 아래 표는 사내 원본 테스트케이스가 아니다.

아래 절차는 테스트계 검증 범위다. 운영계 확인 범위는 ‘수정 후 확인’에 별도로 기재했다.

| 단계 | 테스트 절차 | 기대 결과 |
| --- | --- | --- |
| 1 | 갱신계약의 자동차정보 화면에 진입한다. | 전년도 부속정보가 정상적으로 조회된다. |
| 2 | 외부 차량정보를 조회한다. | 동일한 외부 조회 부속과 기존 입력 부속이 중복정보 조정 대상으로 표시된다. |
| 3 | 외부 조회 할인부속과 기타부속의 선택·수정 가능 여부를 확인한다. | 외부 조회 할인부속은 제거할 수 없고, 기타부속은 선택 해제와 가액 수정이 가능하다. |
| 4 | 중복정보를 조정하고 총차량가액을 확정한다. | 동일 할인부속이 하나만 유지되고 조정된 부속정보를 반영한 총차량가액이 확정된다. |
| 5 | 보험료를 계산하고 청약내용 확인부터 결제·가입 완료까지 진행한다. | 최종 부속정보와 보험료가 청약내용에 반영된 상태로 가입이 완료된다. |
| 6 | 기간계 계약정보와 모니터링 로그를 확인한다. | 기간계의 최종 부속정보·보험료가 화면 결과와 일치하고, 모니터링 로그에서 동일 부속의 중복 반영이 확인되지 않는다. |

## 실제 결과

- 기존 입력 할인부속을 제외하고 외부 조회 할인부속만 유지하도록 조정했으나, 이후 표시된 총차량가액이 상승한 것을 확인했다.
- 다음 단계 선택 시 `부속정보를 확인해 주세요` 팝업이 반복돼 보험료 계산 단계로 진행할 수 없었다.
- 차량모델을 다시 선택하면 보험료 계산 단계까지 진행할 수 있었다.
- 오류 발생 당시 보험료 계산 결과 화면에는 진입하지 못해 실제 보험료 상승 여부는 확인하지 못했다.

`VEH-002`와 `BUG-001`은 동일한 사례를 테스트 검증 관점과 결함 보고 관점으로 각각 정리한 문서다. 오류 재현과 업무 영향은 [BUG-001. 갱신가입 시 차량 부속정보 중복으로 보험료 계산 단계 진행 불가](../bug-reports/BUG-001_갱신가입_차량부속정보_중복오류.md)에서 상세히 정리했다.

## 수정 후 확인

| 구분 | 확인 환경 | 확인 결과 |
| --- | --- | --- |
| 수정 후 재검증 | 테스트계 | 동일 할인부속 하나만 유지, 외부 조회 할인부속 제거 제한, 안내 팝업 반복 미발생, 총차량가액 확정과 보험료 계산 정상 진행을 확인했다. 모니터링 로그에서는 부속정보 중복이 발생하지 않았는지 확인했다. |
| 회귀검증 | 테스트계 | 기타부속 선택 해제·가액 수정, 청약내용, 결제·가입 완료를 확인했다. 기간계에서는 최종 부속정보와 보험료를 확인했다. |
| 운영 이관 후 확인 | 운영계 | PC 웹·모바일 웹·모바일 앱에서 동일한 중복 조건을 재확인했다. 외부 조회 할인부속 하나만 유지, 안내 팝업 반복 미발생과 보험료 계산 단계 진입을 확인했다. 운영계 결제·가입 완료는 확인하지 않았다. |

## QA 판단

수정 후 재검증에서는 동일 할인부속이 하나만 유지되는지, 외부 조회 할인부속의 제거 제한이 적용되는지, 안내 팝업 반복 없이 총차량가액 확정과 보험료 계산이 가능한지 확인했다.

회귀검증에서는 기타부속 선택 해제·가액 수정과 후속 청약·결제·가입 완료 흐름을 확인하고, 기간계의 최종 부속정보와 보험료를 대조했다.

운영계에서는 수정 반영 후 보험료 계산 단계 진입까지 확인했으며, 결제·가입 완료는 검증 범위에 포함하지 않았다.
