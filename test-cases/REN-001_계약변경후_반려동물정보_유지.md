# REN-001. 계약변경 후 갱신 시 반려동물 등록정보 유지

## 개요

| 항목 | 내용 |
| --- | --- |
| 확인 경위 | 고객 문의 후 오류 재현 |
| 검증 목적 | 차량·부속품 변경 후 반려동물 등록정보 유지와 갱신보험료 계산 확인 |
| 대상 흐름 | 계약변경 → 갱신가입 → 등록정보 승계 → 보험료 계산 → 청약내용 확인 → 결제·가입 완료 |
| 검증 관점 | 갱신 데이터 유지·상태 정합성 |
| 확인 환경·채널 | 테스트계·운영계 / PC 웹·모바일 |
| 공유 방식 | Redmine·메신저 |

## 사전조건

- 반려동물 교통사고 위로금 특약이 가입된 계약이다.
- 반려동물 유형과 유효한 동물등록번호가 저장돼 있다.
- 한 마리 또는 여러 마리의 반려동물이 등록돼 있다.
- 차량대체 또는 부속품 추가·삭제 배서를 진행할 수 있다.

## 테스트 절차 및 기대 결과

| 단계 | 테스트 절차 | 기대 결과 |
| --- | --- | --- |
| 1 | 한 마리 또는 여러 마리의 반려동물 정보가 저장된 계약을 확인한다. | 각 반려동물의 특약·유형·등록번호가 정상 조회된다. |
| 2 | 차량대체·부속품 추가·부속품 삭제 조건별로 배서를 진행한다. | 각 배서 이후에도 기존 반려동물 유형과 등록번호가 유지된다. |
| 3 | 배서가 반영된 계약으로 갱신가입을 시작한다. | 기존 특약과 반려동물 등록정보가 자동 승계된다. |
| 4 | 보험료를 계산하고 PC 웹·모바일과 기간계 결과를 비교한다. | 추가특약 오류 없이 보험료가 계산되고 특약상태·유형·등록번호와 보험료가 일치한다. |
| 5 | 청약내용 확인부터 결제·가입 완료까지 진행한다. | 반려동물 특약정보가 유지된 상태로 가입이 완료된다. |

## 실제 결과

보험료 계산을 진행하면 `추가 특약을 확인해 주세요` 팝업이 표시됐고, 팝업 확인 후에도 보험료 계산 결과가 표시되지 않아 다음 단계로 진행할 수 없었다.

기존 반려동물 특약은 선택이 해제돼 있었고 반려동물 유형과 동물등록번호를 불러오지 못했다. 기간계의 갱신 청약정보에도 등록정보가 존재하지 않았다.

최초 문의의 부속품 추가 조건뿐 아니라 차량대체와 부속품 삭제 조건에서도 같은 현상을 재현했다. 고객이 특약·유형·등록번호를 다시 입력해 저장하면 보험료를 계산할 수 있었다.

## 수정 후 확인

| 구분 | 확인 환경 | 확인 결과 |
| --- | --- | --- |
| 수정 후 재검증 | 테스트계 | 차량대체·부속품 추가·삭제 후 반려동물 유형과 등록번호 유지, 갱신 시 자동 승계, 추가특약 팝업 미발생과 보험료 정상 계산을 확인했다. 한 마리와 여러 마리 조건을 각각 확인했다. |
| 회귀검증 | 테스트계 | PC 웹·모바일과 기간계의 특약상태·등록정보·보험료를 대조하고 청약내용과 결제·가입 완료까지 확인했다. |
| 운영 이관 후 확인 | 운영계 | 직접 수행한 계약은 배서청약 완료까지 진행하고 기간계·모니터링 로그에서 반려동물 명세 삭제 여부를 확인했다. 이후 약 1주일간 동일 조건으로 반영된 한 마리·여러 마리 계약에서 명세 유지 여부를 확인했다. 직접 수행한 계약의 최종 반영은 확인하지 않았다. |

## QA 판단

최초 문의의 부속품 추가 조건에서 차량대체·부속품 삭제 조건과 한 마리·여러 마리 등록 조건까지 범위를 확장해 배서 이후의 데이터 유지와 갱신 흐름을 확인했다.
