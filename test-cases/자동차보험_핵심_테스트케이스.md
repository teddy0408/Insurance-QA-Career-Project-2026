# 자동차보험 핵심 테스트케이스

## 1. 문서 개요

본 문서는 자동차보험 가입·갱신·계약변경 과정에서 실제 업무 중 확인한 고객 문의와 운영 오류를 기반으로 작성한 핵심 테스트케이스다.

특정 보험사의 내부 명칭, 실제 고객정보, 차량정보, 보험료, 할인율 및 외부업체명은 일반화했다. 확인하지 않은 개발 원인과 내부 시스템 구조는 작성하지 않았다.

각 사례는 다음 범위를 구분해 작성했다.

- 실제 고객 문의 또는 운영 오류
- 테스트계·운영계에서 직접 확인한 현상
- 개발·현업 담당자에게 전달한 내용
- 수정 반영 후 직접 재검증한 범위

`bug-reports` 폴더에는 실제 오류 중 별도의 결함 보고서로 정리할 필요가 있는 대표 사례만 수록한다. 테스트케이스와 결함 보고서를 일대일로 구성하지 않았으며, `VEH-002`는 `BUG-001`과 같은 사례다. 나머지 사례는 본 문서에 실제 오류와 재검증 내용을 포함했다.

## VEH-002. 외부 차량정보 조회 시 기존 입력 부속의 중복 처리 및 후속 가입 흐름 검증

### 1. 테스트 개요

| 항목 | 내용 |
| --- | --- |
| 대상 흐름 | 갱신계약 자동차정보 조회 → 보험료 계산 → 가입 완료 |
| 테스트 유형 | 외부 연동·데이터 정합성·회귀 |
| 경험 근거 | 실제 오류 확인·수정 후 재검증 |
| 확인 환경 | 테스트계·운영계 |
| 확인 채널 | PC·모바일·기간계·모니터링 로그 |

### 2. 검증 목적 및 업무규칙

갱신계약에 고객이 직접 입력한 할인부속이 존재하고 외부 차량정보에도 같은 부속이 조회될 때, 중복정보가 업무규칙에 따라 정리되고 보험료와 계약정보에 하나의 유효한 부속만 반영되는지 검증한다.

업무규칙은 다음과 같다.

- 외부조회된 할인부속 정보를 우선 적용한다.
- 동일한 할인부속이 중복된 경우 하나만 유지한다.
- 외부조회된 할인부속은 고객이 임의로 제거할 수 없도록 처리한다.
- 기타부속은 고객이 선택을 해제하거나 가액을 수정할 수 있다.
- 부속가액과 할인정보는 보험료 및 계약정보에 중복 반영되면 안 된다.

### 3. 사전조건

- 갱신계약에 고객이 직접 입력한 할인부속 A가 존재한다.
- 외부 차량정보 조회 결과에도 동일한 할인부속 A가 존재한다.
- 고객이 선택하거나 가액을 수정할 수 있는 기타부속이 존재한다.

### 4. 테스트 절차 및 기대결과

| 단계 | 테스트 절차 | 기대결과 |
| --- | --- | --- |
| 1 | 갱신계약의 자동차정보 화면에 진입한다. | 전년도 부속정보가 정상적으로 조회된다. |
| 2 | 외부 차량정보 조회를 실행한다. | 외부조회된 할인부속과 기존 입력 부속의 중복 여부를 비교한다. |
| 3 | 중복정보 조정 팝업을 확인한다. | 부속명·최초가액·현재가액·부속 여부가 표시된다. |
| 4 | 외부조회 할인부속과 기타부속의 선택·수정 가능 여부를 확인한다. | 할인부속은 제거할 수 없고 기타부속은 선택 해제와 가액 수정이 가능하다. |
| 5 | 중복정보를 조정하고 보험료를 계산한다. | 할인부속이 하나만 적용되고 보험료가 정상 계산된다. |
| 6 | 청약내용 확인부터 결제·가입 완료까지 진행한다. | 부속정보와 보험료가 유지된 상태로 가입이 완료된다. |
| 7 | 기간계와 모니터링 로그를 확인한다. | 최종 부속정보와 보험료가 정상적으로 반영된다. |

### 5. 실제 오류

중복정보를 조정한 후에도 동일한 부속정보가 정상적으로 정리되지 않았다. 다음 단계를 선택하면 `부속정보를 확인해 주세요` 팝업이 반복 표시됐고, 보험료 계산 단계로 진행할 수 없었다.

실제 실패 결과, 오류 전달 내용 및 수정 결과는 [BUG-001 갱신가입 차량부속정보 중복오류](../bug-reports/BUG-001_갱신가입_차량부속정보_중복오류.md)에서 별도로 정리한다.

### 6. 수정 및 회귀검증

확인 결과를 Redmine과 메신저로 전달한 후 수정사항이 반영됐으며 다음 항목을 재검증했다.

#### 재검증 항목

- 외부조회 할인부속 우선 적용
- 동일 할인부속 하나만 유지
- 외부조회 할인부속 제거 제한
- 기타부속 선택 해제 및 가액 수정
- 보험료 정상 계산
- 청약내용 확인
- 결제 및 가입 완료
- 모니터링 로그에서 최종 부속정보가 중복 반영되지 않는지 확인
-
#### 검증 조건 및 확인 환경

갱신계약에서 기존 입력 부속과 외부조회 부속이 중복되는 조건을 사용했다. 테스트계에서 PC·모바일과 기간계 결과를 비교했으며, 운영 이관 후 PC·모바일의 가입 흐름, 기간계 반영 결과 및 모니터링 로그를 다시 확인했다.

### 7. 역할 및 업무 영향

중복정보 조정 팝업만 확인하지 않고 최종 유효 부속, 보험료, 청약정보 및 계약정보까지 확인했다. 수정 반영 후에는 보험료 계산부터 결제·가입 완료까지 재검증했다.

동일한 부속정보가 중복된 상태로 남으면 안내 팝업이 반복되고 보험료 계산 단계로 진행할 수 없다. 따라서 화면의 중복 처리 결과와 후속 계약정보의 정합성을 함께 검증했다.

## PRM-002. 갱신계약의 내장형 영상기록장치 자동 승계 시 할인율 및 보험료 정합성

### 1. 테스트 개요

| 항목 | 내용 |
| --- | --- |
| 대상 흐름 | 자동차보험 갱신가입 |
| 테스트 유형 | 자동 승계·채널 정합성·회귀 |
| 경험 근거 | 고객 문의 기반 오류 확인·수정 후 재검증 |
| 확인 환경 | 테스트계·운영계 |
| 확인 채널 | PC·모바일·기간계 |

### 2. 검증 목적 및 업무규칙

전년도 계약의 내장형 영상기록장치 정보가 갱신계약으로 자동 승계될 때 장치 유형이 유지되고, 해당 유형에 맞는 할인율과 보험료가 적용되는지 검증한다.

업무규칙은 다음과 같다.

- 자동 승계된 내장형 영상기록장치에는 내장형 할인율이 적용돼야 한다.
- 고객이 장치 유형을 다시 선택하지 않아도 기존 정보가 정상 반영돼야 한다.
- 동일한 계약조건에서는 PC·모바일·기간계의 장치 유형, 할인율 및 보험료가 일치해야 한다.
- 신규·갱신 및 차량·장치 유형별 할인율이 각각의 기준에 맞게 적용돼야 한다.

### 3. 사전조건

- 전년도 계약에 내장형 영상기록장치 할인특약이 가입돼 있다.
- 특정 수입차량의 갱신가입 조건이다.
- 전년도 장치정보가 갱신 화면으로 자동 승계된다.
- 일반형과 내장형 영상기록장치에 서로 다른 할인율이 적용된다.

### 4. 테스트 절차 및 기대결과

| 단계 | 테스트 절차 | 기대결과 |
| --- | --- | --- |
| 1 | 특정 수입차의 갱신가입을 시작한다. | 전년도 내장형 장치정보가 자동 승계된다. |
| 2 | 장치 유형을 다시 선택하지 않고 보험료를 계산한다. | 내장형 할인율과 보험료가 적용된다. |
| 3 | PC·모바일의 결과를 확인한다. | 두 채널의 장치 유형·할인율·보험료가 일치한다. |
| 4 | 기간계 결과와 비교한다. | 온라인 채널과 기간계의 결과가 일치한다. |
| 5 | 내장형 장치를 수동으로 다시 선택해 재계산한다. | 자동 승계 상태와 수동 선택 상태의 결과가 일치한다. |
| 6 | 청약내용 확인부터 결제·가입 완료까지 진행한다. | 할인율과 보험료가 유지된 상태로 가입이 완료된다. |

### 5. 실제 오류

특정 수입차의 갱신가입에서 내장형 장치정보가 자동 승계되면 PC와 모바일에 일반형 할인율이 적용됐다.

기간계에는 내장형 할인율이 정상적으로 적용됐으며, 온라인 갱신보험료가 기간계에서 산출된 보험료보다 높게 계산됐다.

내장형 장치를 수동으로 다시 선택하면 정상 할인율이 적용됐다. 신규가입에서는 국산차와 수입차 모두 정상적으로 계산됐다.

고객 문의를 바탕으로 테스트계와 운영계에서 동일한 현상을 확인했다.

### 6. 수정 및 회귀검증

확인 결과를 Redmine과 메신저로 전달했다. 현업에서 자동 승계 시 장치 유형의 적용 기준을 정리한 후 수정사항이 반영됐다.

#### 재검증 항목

- 자동 승계된 내장형 장치정보 유지
- 장치 유형에 맞는 할인율 적용
- 할인율에 따른 보험료 정상 계산
- 자동 승계와 수동 재선택 결과 일치
- PC·모바일·기간계의 장치 유형·할인율·보험료 일치
- 청약내용 확인
- 결제 및 가입 완료

#### 검증 조건 및 확인 환경

신규·갱신, 국산차·수입차, 일반형·내장형 영상기록장치 조건을 조합해 확인했다. 테스트계에서 PC·모바일과 기간계 결과를 비교했으며, 운영 이관 후 동일한 주요 조건과 가입 완료 결과를 다시 확인했다.

### 7. 역할 및 업무 영향

고객 문의를 바탕으로 자동 승계와 수동 재선택 조건을 비교해 오류 발생 조건을 확인했다. 확인 결과를 개발·현업 담당자에게 전달하고, 수정 후 장치 유형·할인율·보험료와 가입 완료 결과를 재검증했다.

자동 승계된 장치정보가 잘못 반영되면 온라인 보험료와 고객센터에서 안내하는 보험료가 달라질 수 있다. 확인하지 않은 개발 원인은 작성하지 않고 직접 비교한 결과만 기록했다.

## EVD-001. 외부 주행거리 조회 실패 시 사진형 마일리지 특약 전환 및 정산 검증

### 1. 테스트 개요

| 항목 | 내용 |
| --- | --- |
| 대상 흐름 | 커넥티드 마일리지 특약 갱신 및 정산 |
| 테스트 유형 | 외부 연동·대체 흐름·상태전이·회귀 |
| 경험 근거 | 고객 문의 기반 오류 확인·수정 후 재검증 |
| 확인 환경 | 테스트계·운영계 |
| 확인 채널 | PC·모바일·기간계·모니터링 로그 |

### 2. 검증 목적 및 업무규칙

전년도 계약에 커넥티드 마일리지 특약이 가입된 갱신계약에서 외부 주행거리 조회가 실패할 경우, 사진형 마일리지 특약으로 정상 전환되고 사진등록과 정산 절차가 제공되는지 검증한다.

업무규칙은 다음과 같다.

- 외부조회에 성공하면 조회된 주행거리로 정산한다.
- 외부조회에 실패하면 커넥티드형을 해제하고 사진형으로 전환한다.
- 사진형으로 전환되면 정산에 필요한 사진등록 화면을 즉시 표시한다.
- 커넥티드형과 사진형 특약을 동시에 적용하지 않는다.
- 기존 커넥티드 할인과 사진형 할인을 중복 반영하지 않는다.

### 3. 사전조건

- 전년도 계약에 커넥티드 마일리지 특약이 가입돼 있다.
- 커넥티드 서비스가 해지됐거나 외부기관에서 주행거리 정보를 제공하지 않는 조건이다.
- 외부조회 실패 시 사진형 마일리지 특약으로 전환할 수 있다.

### 4. 테스트 절차 및 기대결과

| 단계 | 테스트 절차 | 기대결과 |
| --- | --- | --- |
| 1 | 커넥티드 마일리지 특약 가입계약으로 갱신을 시작한다. | 기존 특약정보가 정상적으로 조회된다. |
| 2 | 외부 주행거리 조회를 실행한다. | 외부기관으로 조회 요청이 전달된다. |
| 3 | 외부조회 실패 결과를 확인한다. | 조회 실패 팝업이 표시된다. |
| 4 | 팝업을 확인한다. | 커넥티드형이 해제되고 사진형으로 전환된다. |
| 5 | 전환 직후 화면을 확인한다. | 사진등록 화면이 즉시 표시된다. |
| 6 | 사진을 등록하고 마일리지 정산을 진행한다. | 사진정보를 기준으로 정산이 처리된다. |
| 7 | 적용 특약과 보험료를 확인한다. | 사진형만 적용되고 할인정보가 중복되지 않는다. |
| 8 | 청약내용 확인부터 결제·가입 완료까지 진행한다. | 정산 결과가 유지된 상태로 가입이 완료된다. |
| 9 | 기간계와 발송 결과를 확인한다. | 특약·정산정보와 알림 결과가 정상 반영된다. |

### 5. 실제 오류

외부조회 실패 팝업 확인 후 커넥티드형은 해제되고 사진형으로 자동 변경됐다.

사진형으로 변경된 직후 사진등록 화면이 표시되지 않았으며, 사용자는 사진을 등록하지 않은 상태로 다음 단계로 이동할 수 있었다. 다음 단계로 이동한 뒤 이전 단계로 돌아오면 사진등록 화면이 표시됐다.

특약 전환은 처리됐지만 사진 정산을 위한 후속 화면이 정상 순서로 제공되지 않았다.

외부조회 실패 자체는 보험사 내부 오류가 아니었다. 커넥티드 서비스 해지 또는 외부기관의 주행거리 정보 미제공으로 조회가 실패할 수 있으며, 수정 대상은 조회 실패 이후의 사진형 정산 흐름이었다.

### 6. 수정 및 회귀검증

고객 문의 내용을 Redmine과 메신저로 전달한 후, 외부조회 실패 시 사진등록 화면이 즉시 표시되도록 수정됐다.

#### 재검증 항목

- 조회 실패 팝업 노출
- 커넥티드형 특약 해제
- 사진형 마일리지 특약 자동 전환
- 사진등록 화면 즉시 노출
- 사진 기준 마일리지 정산
- 커넥티드형·사진형 특약 동시 적용 방지
- 기존 할인과 사진형 할인 중복 미발생
- 청약내용 확인
- 결제 및 가입 완료
- 기간계 특약·정산정보 반영
- 알림톡·문자·이메일 발송

#### 검증 조건 및 확인 환경

커넥티드 서비스 해지와 외부기관 주행거리 정보 미제공 조건을 각각 확인했다. 테스트계에서 PC·모바일, 기간계 및 모니터링 로그를 확인했으며, 운영 이관 후 사진형 전환부터 가입 완료와 알림 발송까지 다시 확인했다.

### 7. 역할 및 업무 영향

고객 문의를 바탕으로 외부조회 실패 이후 사진형 전환과 사진등록 화면의 노출 순서를 확인했다. 확인 결과를 전달한 후 수정된 대체 흐름과 마일리지 정산, 가입 완료 및 알림 결과를 재검증했다.

외부조회 실패와 보험사 내부 오류를 구분하고, 실패 이후 고객이 이용해야 하는 대체 흐름이 정상적으로 연결되는지를 검증했다.

## REN-001. 차량대체·부속 변경 후 반려동물 등록정보 유지 및 갱신 보험료 계산 검증

### 1. 테스트 개요

| 항목 | 내용 |
| --- | --- |
| 대상 흐름 | 계약변경 이후 자동차보험 갱신가입 |
| 테스트 유형 | 데이터 유지·상태 정합성·회귀 |
| 경험 근거 | 고객 문의 기반 오류 확인·수정 후 재검증 |
| 확인 환경 | 테스트계·운영계 |
| 확인 채널 | PC·모바일·기간계 |

### 2. 검증 목적 및 업무규칙

반려동물 교통사고 위로금 특약이 가입된 계약에서 차량대체 또는 부속품 추가·삭제 배서를 진행한 후에도 반려동물 유형과 동물등록번호가 유지되고, 해당 계약의 갱신보험료가 정상적으로 계산되는지 검증한다.

업무규칙은 다음과 같다.

- 차량대체와 부속품 변경은 반려동물 등록정보를 변경하는 배서가 아니다.
- 배서 후에도 기존 반려동물 유형과 동물등록번호를 유지해야 한다.
- 갱신 시 기존 특약 가입상태와 등록정보가 정상적으로 승계돼야 한다.
- 고객이 기존 정보를 다시 입력하지 않아도 갱신보험료가 계산돼야 한다.
- 여러 마리가 등록된 계약에서도 각각의 정보가 유지돼야 한다.

### 3. 사전조건

- 반려동물 교통사고 위로금 특약이 가입된 계약이다.
- 반려동물 유형과 유효한 동물등록번호가 저장돼 있다.
- 한 마리 또는 여러 마리의 반려동물이 등록돼 있다.
- 해당 계약으로 차량대체 또는 부속품 추가·삭제 배서를 진행할 수 있다.

### 4. 테스트 절차 및 기대결과

| 단계 | 테스트 절차 | 기대결과 |
| --- | --- | --- |
| 1 | 특약과 반려동물 등록정보가 저장된 계약을 확인한다. | 특약·반려동물 유형·등록번호가 정상 조회된다. |
| 2 | 차량대체 배서를 진행한다. | 배서 후에도 기존 반려동물 정보가 유지된다. |
| 3 | 부속품 추가 또는 삭제 배서를 진행한다. | 배서 후에도 기존 반려동물 정보가 유지된다. |
| 4 | 해당 계약으로 갱신가입을 시작한다. | 기존 특약과 등록정보가 자동 승계된다. |
| 5 | 보험료 계산결과 화면으로 진입한다. | 추가특약 오류 없이 보험료가 계산된다. |
| 6 | PC·모바일 결과와 기간계 정보를 확인한다. | 특약상태·등록정보·보험료가 일치한다. |
| 7 | 청약내용 확인부터 결제·가입 완료까지 진행한다. | 특약정보가 유지된 상태로 가입이 완료된다. |

### 5. 실제 오류

최초 문의는 부속품 추가 배서를 진행한 고객의 갱신가입에서 발생했다.

보험료 계산결과 화면에 진입하면 `추가 특약을 확인해주세요` 팝업이 표시됐다. 팝업 확인 후에도 보험료가 계산되지 않았고 다음 단계 버튼이 작동하지 않았다.

추가특약 화면에서는 기존 반려동물 특약의 선택이 해제돼 있었고, 기존 반려동물 유형과 동물등록번호를 불러오지 못했다. 갱신 청약번호를 기간계에서 확인했을 때도 반려동물 등록정보가 존재하지 않았다.

해당 현상은 PC와 모바일에서 모두 발생했다. 확인 과정에서 차량대체와 부속품 삭제 배서에서도 같은 현상을 재현했다. 배서이력은 남아 있었지만 반려동물 유형과 동물등록번호는 유지되지 않았다.

고객이 반려동물 특약을 다시 선택하고 유형과 등록번호를 입력한 뒤 저장하면 보험료를 다시 계산할 수 있었다.

### 6. 수정 및 회귀검증

확인 결과를 Redmine과 메신저로 전달했다. 현업과 개발 담당자 사이의 구체적인 수정 과정과 등록정보 삭제의 개발 원인은 직접 확인하지 못했다.

#### 재검증 항목

- 차량대체 후 반려동물 유형·등록번호 유지
- 부속품 추가 후 반려동물 유형·등록번호 유지
- 부속품 삭제 후 반려동물 유형·등록번호 유지
- 갱신 시 기존 특약 가입상태 유지
- 갱신 시 반려동물 등록정보 자동 승계
- 추가특약 오류 없이 보험료 정상 계산
- 청약내용 확인
- 결제 및 가입 완료

#### 검증 조건 및 확인 환경

차량대체, 부속품 추가, 부속품 삭제와 반려동물 한 마리·여러 마리 등록조건을 사용했다. 테스트계에서 PC·모바일과 기간계 결과를 확인했으며, 운영 이관 후 등록정보 유지부터 갱신보험료 계산과 가입 완료까지 다시 확인했다.

### 7. 역할 및 업무 영향

최초 고객 문의의 부속품 추가 조건뿐 아니라 차량대체와 부속품 삭제 조건을 추가로 재현해 영향 범위를 확인했다. 수정 후에는 세 가지 배서와 여러 마리 등록조건을 포함해 갱신보험료 계산부터 가입 완료까지 재검증했다.

배서와 직접 관련 없는 반려동물 등록정보가 삭제되면 갱신계약에서 기존 정보를 다시 입력해야 한다. 등록번호를 즉시 확인하기 어려운 경우 갱신 진행이 중단될 수 있으므로 배서 완료 시점의 정보 유지와 이후 갱신 흐름을 함께 검증했다.
