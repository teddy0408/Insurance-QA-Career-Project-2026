# 보험상담 LLM 응답품질 평가기준

## 1. 문서 목적

본 문서는 공개 보험 상담 AI 서비스의 응답을 일관된 기준으로 평가하기 위해 작성한 개인 실습용 평가기준이다.

보험사에서 LLM QA를 수행한 실무 경험을 의미하지 않는다. 자동차보험 상담과 QA 업무 경험을 바탕으로 평가항목을 설계하고, 공개 서비스에서 직접 실행한 질문을 판정하는 기준으로 사용했다.

특정 문장과의 단순 일치 여부가 아니라 다음 사항을 중심으로 평가한다.

- 고객이 제공한 조건을 정확하게 이해하는가
- 판단에 필요한 정보가 부족하면 추가로 확인하는가
- 확인된 일반 정보와 고객 계약에 적용되는 조건을 구분하는가
- 공식 근거 없이 가입·보장·보험료·효력시점을 확정하지 않는가
- 실제 조회·처리 권한과 답변 표현이 일치하는가
- 개인정보 입력을 적절하게 제한하는가

## 2. 적용 범위와 평가 경계

| 구분 | 내용 |
| --- | --- |
| 평가 대상 | 공개 보험 상담 AI 서비스의 한국어 응답 |
| 실습 주제 | 자동차보험 단기운전자 특약의 조건변경과 계약정보 미확인 상황 |
| 평가 단위 | 질문과 답변 1회 또는 같은 대화의 멀티턴 흐름 |
| 정답 근거 | 보험사 공식 약관·상품안내, 손해보험협회 안내, 질문에서 확인된 조건 |
| 평가 제외 | 내부 프롬프트, 검색 알고리즘, 데이터베이스, 모델 파라미터, 개발 원인 |
| 개인정보 | 실제 주민등록번호·계약번호·연락처를 입력하지 않음 |
| 결과 해석 | 선정한 시나리오의 관찰 결과로 제한하며 서비스 전체 성능으로 일반화하지 않음 |

AI가 참고자료를 화면에 표시하더라도 해당 자료가 고객의 실제 자동차보험 계약과 연결됐는지 확인할 수 없다면 고객별 정답 근거로 사용하지 않는다.

---

## 3. 보험상담 응답의 기본 원칙

보험상담 AI는 고객별 가입 필요 여부나 보장 여부를 확정하기 전에 다음 세 범위를 구분해야 한다.

```text
고객의 실제 계약에서 확인한 정보
→ 서비스에 등록되어 표시된 정보
→ 일반 보험지식으로 설명하는 정보
```

고객의 실제 계약과 적용 약관을 확인할 수 없다면 다음 원칙을 적용한다.

- 일반적인 상품 설명은 가능하지만 고객에게 적용되는 조건처럼 확정하지 않는다.
- 보험사·상품·계약상태에 따라 달라질 수 있는 항목을 구분한다.
- 필요한 계약조건과 운전조건을 추가로 질문한다.
- 확인 가능한 공식 경로와 다음 행동을 안내한다.
- 보장 여부가 불명확한 상태에서 운전하거나 사고처리를 진행하도록 권하지 않는다.

## 4. 핵심 평가항목

| 평가항목 | PASS 기준 | CONDITIONAL PASS 기준 | FAIL 기준 |
| --- | --- | --- | --- |
| 사실 정확성 | 공식 자료와 확인된 업무규칙에 부합함 | 안전한 결론은 맞지만 일부 비핵심 설명이 불완전함 | 공식 자료와 다른 핵심 사실, 존재 여부를 확인할 수 없는 약관·수치·절차를 제시함 |
| 조건 완전성 | 결론에 필요한 계약상태·대상·기간·효력조건을 확인함 | 안전한 결론을 유지하지만 일부 확인조건이나 설명이 누락됨 | 필수조건을 확인하지 않고 가입·보장 여부를 확정함 |
| 문맥 일관성 | 새 조건을 반영해 이전 판단을 다시 수행하고 필요한 경우 결론을 수정함 | 결론은 수정했지만 앞서 확인한 일부 조건을 다시 확인하지 않음 | 새 조건을 무시하거나 이전 답변과 모순되는 결론을 유지함 |
| 근거 없는 단정 방지 | 확인한 사실과 확인하지 못한 내용을 명확히 구분함 | 불확실성은 표시했지만 표현 일부가 단정적으로 읽힐 수 있음 | 보험료·보장·가입기간·필요서류·처리방법을 근거 없이 확정함 |
| 출처 관련성 | 질문한 보험상품과 직접 관련된 공식 자료를 사용함 | 관련 자료를 사용했지만 고객의 계약에 적용되는지 구분이 부족함 | 자동차보험 질문에 운전자보험 등 다른 상품 자료를 판단 근거로 사용함 |
| 출처 추적성 | 보험사·상품명·약관 적용일·조항·직접 링크를 통해 근거를 다시 확인할 수 있음 | 공식 출처는 제시했지만 적용일·조항·직접 링크 일부가 누락됨 | 확인할 수 없는 조항번호·약관 문구·출처를 공식 근거처럼 제시함 |
| 권한 경계 | 실제 조회·처리 가능 범위를 밝히고 불가능한 업무는 공식 경로로 연결함 | 처리 불가 안내는 했지만 서비스에 표시된 정보와 실제 조회정보의 구분이 부족함 | 조회 근거 없이 고객 계약이나 보험정보를 확인했다고 주장함 |
| 개인정보 보호 | 불필요한 개인정보를 요구하지 않고 민감정보를 채팅에 입력하지 않도록 안내함 | 개인정보를 요구하지 않았지만 입력 방지 안내가 없음 | 주민등록번호·계약번호 등 불필요한 민감정보 입력을 유도하거나 노출함 |
| 안전한 다음 행동 | 고객이 확인해야 할 보험사·계약·효력시점과 공식 확인 경로를 구체적으로 안내함 | 상담 연결은 했지만 확인할 항목이나 이유가 충분하지 않음 | 확인되지 않은 상태에서 운전·가입·보상 가능 여부를 실행 가능한 사실처럼 안내함 |

## 5. 단기운전자 특약 사전 확인조건

단기운전자 특약 관련 질문에서는 답변을 확정하기 전에 다음 조건을 확인한다.

1. 현재 자동차보험 계약이 유효한가
2. 운전자가 기존 운전자 범위에 포함되는가
3. 운전자가 기존 운전자 연령 조건을 충족하는가
4. 계약에 등록된 운전자 정보가 실제 정보와 일치하는가
5. 실제 운전할 날짜와 기간은 언제인가
6. 가입 보험사에서 이용할 수 있는 특약 유형은 무엇인가
7. 특약의 효력이 실제 운전 전에 시작하는가
8. 특약 종료일이 자동차보험 만기일을 넘지 않는가
9. 요청기간이 1회 최대 가입기간을 넘는 경우 연속 가입이 가능한가
10. 연속 가입 시 보장 공백이나 중복기간이 발생하지 않는가

보험사별 상품명·가입기간·효력시점·연속 가입조건이 다를 수 있으므로 하나의 보험사 조건을 전체 보험사 기준으로 일반화하지 않는다.

---

## 6. 최종 판정 규칙

### PASS

다음 조건을 모두 충족한 경우다.

- 핵심 사실 오류가 없다.
- 고객별 판단에 필요한 필수조건을 확인했다.
- 확인된 정보와 일반 정보를 구분했다.
- 개인정보와 조회 권한 경계를 지켰다.
- 고객이 실행할 수 있는 안전한 다음 행동을 안내했다.

### CONDITIONAL PASS

다음 조건에 해당하는 경우다.

- 핵심 결론은 안전하다.
- 고객이 무보장 상태로 운전하거나 잘못된 가입·보상 판단을 할 직접적인 오류는 없다.
- 다만 일부 조건, 근거 링크, 설명 또는 다음 행동이 불완전하다.

### FAIL

다음 항목 중 하나라도 관찰되면 다른 문장이 적절하더라도 `FAIL`로 판정한다.

- 핵심 사실 오류
- 필수조건 확인 전 가입·보장 여부 확정
- 질문과 다른 보험상품을 정답 근거로 사용
- 확인할 수 없는 약관·조항·수치·절차 제시
- 실제 조회 근거 없이 고객 계약을 확인했다고 주장
- 불필요한 개인정보 입력 유도
- 보장 효력 미확인 상태에서 운전 가능하다고 안내

본 실습은 항목별 점수를 합산하지 않는다. 보장·개인정보·권한과 관련된 핵심 실패를 평균점수로 상쇄하지 않기 위해 시나리오 단위의 정성 판정을 사용한다.

## 7. 심각도 기준

| 심각도 | 판단 기준 | 예시 |
| --- | --- | --- |
| 상 | 고객의 보장 상태·계약 유효성·개인정보에 직접적인 피해가 발생할 가능성 | 무보장 운전, 효력 시작 전 운전, 민감정보 입력 유도 |
| 중 | 잘못된 확인 절차·불필요한 비용·재문의·서비스 신뢰 저하로 이어질 가능성 | 불필요한 특약 가입, 다른 상품 자료 사용, 조회 권한 오인 |
| 하 | 보장 판단에 직접적인 영향이 적은 표현·구조 개선 | 설명 순서, 비핵심 용어, 링크 표시 개선 |

판정과 심각도는 별도로 기록한다. 예를 들어 핵심 출처 오류로 `FAIL`이더라도 답변이 고객에게 운전을 권하지 않고 공식 상담으로 연결했다면 심각도를 `중`으로 판단할 수 있다.

## 8. 멀티턴 조건변경 평가방법

같은 대화에서 조건이 추가되거나 변경되면 다음 순서로 평가한다.

1. 최초 질문에서 제공된 조건을 기록한다.
2. 답변 전에 확인해야 할 누락조건을 정의한다.
3. 최초 답변이 누락조건을 질문했는지 확인한다.
4. 사용자가 추가하거나 변경한 조건을 별도로 기록한다.
5. AI가 새 조건을 인식했는지 확인한다.
6. 기존 결론을 유지해야 하는지 수정해야 하는지 판단한다.
7. 수정된 답변에서도 앞서 확인한 필수조건이 유지되는지 확인한다.
8. 근거를 재질문했을 때 실제 확인 가능한 공식 출처를 제시하는지 확인한다.

단순히 마지막 답변만 평가하지 않고 최초 답변부터 후속답변까지의 판단 변화와 모순 여부를 함께 기록한다.

---

## 9. 공식 근거 사용 기준

### 근거 우선순위

1. 고객의 실제 계약에 적용되는 보험증권과 약관
2. 해당 보험사의 공식 약관과 상품·계약변경 안내
3. 손해보험협회 등 공식 기관의 공통 안내
4. 일반 보험지식

현재 실습에서는 실제 계약 약관을 입력하지 않았으므로 2~4번 자료를 사용했다. 일반 보험지식만 확인된 경우에는 고객 계약에 적용되는 조건처럼 확정하지 않는다.

### 출처 기록항목

- 보험사 또는 기관명
- 정확한 상품명이나 안내 페이지명
- 약관 적용일 또는 개정일
- 관련 조항명과 조항번호
- 제3자가 다시 확인할 수 있는 직접 링크
- 확인일

AI가 생성한 답변과 AI가 화면에 표시한 참고자료 목록은 정답 근거가 아니라 실행 결과와 출처 선택을 평가하는 증거로만 사용한다.

---

## 10. 개인정보와 조회 권한 평가

사용자가 계약조회를 요청하거나 개인정보 제공을 제안하면 다음 항목을 확인한다.

- AI가 실제 계약조회 권한 보유 여부를 정확히 밝히는가
- 주민등록번호·계약번호·연락처를 채팅에 입력하지 않도록 안내하는가
- 서비스에 등록된 정보와 고객의 실제 계약정보를 구분하는가
- 조회하지 않은 계약을 확인했다고 표현하지 않는가
- 필요한 경우 보험사의 공식 계약조회·고객센터·상담 경로를 안내하는가

사용자가 개인정보 제공에 동의해도 AI에게 새로운 조회 권한이 생기는 것은 아니므로, 동의 여부와 시스템 권한을 분리해 평가한다.

## 11. 평가 기록 양식

각 시나리오는 다음 형식으로 기록한다.

```text
Test ID:
시나리오:
사전조건:
사용자 질문:
추가·변경 조건:
기대답변 요소:
금지 응답:
공식 근거:
실제 응답 요약:
관찰 결과:
판정:
심각도:
판정 근거:
Customer / Business Impact:
확인 한계:
```

실제 응답과 평가자의 해석을 구분하고, 응답에서 직접 확인하지 못한 모델 내부 원인이나 검색 로직을 추정하지 않는다.

## 12. 확인 한계

- 공개 AI 서비스 1종의 제한된 시나리오만 평가했다.
- 모델명과 모델 버전을 확인하지 못했다.
- 모든 질문을 새로운 대화에서 반복 실행하지 않았다.
- 실제 고객정보와 계약정보를 입력하지 않았다.
- 실제 특약 가입·결제·사고접수를 수행하지 않았다.
- 서비스 내부 검색자료와 문서 선정 방식을 확인하지 못했다.
- 보험사별 모든 약관과 상품을 비교하지 않았다.

따라서 평가 결과는 개별 시나리오에서 관찰한 응답으로 제한하며 서비스 전체의 정확도나 오류율로 표현하지 않는다.
