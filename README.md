# Insurance Product QA Portfolio

웹·모바일 보험 서비스에서 변경 요구사항 검증과 운영 이슈 재현, 수정 후 재검증·회귀검증, 운영 이관 후 확인을 수행해 왔다.

보험 도메인 10년 이상의 상담·업무지원 경험을 바탕으로 계약 상태·효력 시점·보험료·배서 결과를 연결해 오류 조건과 고객 영향을 확인해 왔다.

이 포트폴리오에는 자동차보험 가입·갱신·계약변경 과정에서 고객 문의와 테스트 요청을 검증 조건으로 구조화하고, 사용자 화면·기간계·모니터링 로그를 대조한 실무 사례를 정리했다.

API 검증 설계와 생성형 보험 상담 LLM 응답 평가는 개인 실습으로 구분했다.

| 역량 | 수행 방식 |

| 생성형 AI 응답 품질 평가(개인 실습) | 사실·근거 정확성, 조건 확인·판단 완전성, 문맥 일관성, 권한·개인정보 보호와 안전한 다음 행동을 기준으로 평가 |
| 협업·운영 이관 지원 | Redmine·메신저로 발생 조건과 영향 범위를 공유하고, 확정된 수정 범위에 따라 재검증·회귀검증 및 운영 반영 후 핵심 흐름 확인 |

## 대표 검증 사례

### 1. 갱신가입 차량부속정보 중복

- **문제** 기존 입력 부속과 외부 조회 부속이 중복된 상태에서 안내 팝업이 반복되고 보험료 계산 단계로 진행하지 못함
- **판단·행동** 화면 표시 문제가 아니라 부속정보 병합과 총차량가액·보험료·계약정보의 정합성에 영향을 줄 수 있는 조건으로 판단하고, 테스트계의 PC 웹·모바일에서 동일 조건을 재현해 발생 조건과 영향 범위를 공유
- **결과** 테스트계에서 동일 할인부속의 단일 반영, 총차량가액 확정, 보험료 계산과 청약·결제·가입 완료를 확인했다. 기간계의 최종 부속정보·보험료와 모니터링 로그를 대조했으며, 운영계에서는 PC 웹·모바일의 중복 처리와 보험료 계산 단계 진입까지 재확인했다.

### 2. 보험 효력 개시 전 실시간 단기운전자 특약 가입

- **문제** 자동차보험 효력이 개시되지 않은 계약에서 실시간 단기운전자 특약 가입이 가능했고, 고객 문의에서 실제 결제 사실을 확인
- **판단·행동** 자동차보험 계약의 효력 상태와 특약 가입 가능 시점을 연결해 모바일 웹·모바일 앱에서 재현하고, 테스트계에서 결제·배서계약 생성과 기간계 배서내역까지 확인
- **결과** 수정 후 테스트계·운영계의 모바일 웹·모바일 앱에서 효력 개시 전 신청이 차단되는지 확인했다. 회귀검증으로 효력이 시작된 정상 계약의 실시간 단기운전자 특약과 기존 정상 단기운전자 특약 흐름을 확인했다.

### 3. 마이데이터 연계 대중교통 할인특약 정합성 확인

- **검증 배경** 대중교통 할인특약의 실적 조회수단에 마이데이터 서비스가 추가되어, 기존 동의 정보를 통한 실적 자동 조회와 특약 적용 흐름을 확인했다.
- **검증 범위** 모바일 웹·모바일 앱에서 조회 동의·본인인증, 실적 자동 조회와 특약 적용, 타 조회수단과의 중복 적용 여부, 보험료·할인율, 가입·결제 흐름을 확인하고, 기간계에서 계약 생성 결과와 보험료를 대조했다.
- **확인 결과** 갱신 설계의 기간계 보험료와 홈페이지 보험료 차이를 재현하고, 마이데이터 정보 전달 여부와 할인특약 반영 기준을 관계 부서에 확인했다. 채널별 업무 정의에 따른 차이로 확인되어 시스템 수정 없이 기존 기준을 유지했다.

## 공개 범위

실무 사례는 보험사·고객·차량·계약을 식별할 수 없도록 일반화했다. 직접 확인한 결과와 개인 검증 설계·평가 영역은 각 문서에 구분해 기록했다.
