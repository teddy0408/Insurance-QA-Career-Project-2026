# Insurance QA Career Project 2026

보험 고객상담 및 다이렉트 업무지원 과정에서 쌓은 도메인 경험과 테스트 참여 경험을 바탕으로 작성한 보험·핀테크 QA 포트폴리오다.

자동차보험 가입·갱신·계약변경 과정의 업무규칙을 분석하고, 실제 업무에서 확인한 오류와 수정 후 재검증 범위를 테스트케이스와 결함 보고서로 정리했다.

공식 QA 직무로 수행하지 않은 경험을 QA 경력으로 과장하지 않았으며, 실무 경험을 기반으로 작성한 문서와 개인 실습 문서를 구분했다.

## 프로젝트 핵심 범위

- 자동차보험 가입·갱신·계약변경 업무규칙 분석
- 외부 조회정보와 기존 계약정보의 데이터 정합성 검증
- PC·모바일·기간계 결과 비교
- 보험료 계산부터 결제·가입 완료까지 후속 흐름 확인
- 고객 문의와 운영 오류의 재현 조건 확인
- 오류 전달 및 수정 후 회귀검증
- API 테스트 및 LLM QA 개인 실습

## 경험 구분

| 구분 | 범위 |
| --- | --- |
| 실무 경험 기반 | 보험 업무규칙 확인, 테스트 요청 확인, 테스트계 검증, 운영 이관 후 웹·모바일·기간계 확인, 오류 전달 및 수정 후 재검증 |
| 개인 실습 | 화면 흐름 기반 API 요청·응답 검증 설계, 보험 상담 LLM 응답 품질 평가 |

API 테스트와 LLM QA는 직장 실무 경험이 아닌 개인 실습으로 작성한다.

### 4. API 테스트 — 개인 실습 예정

[API 테스트](./api-testing/README.md)

자동차보험 화면에서 확인할 수 있는 입력값·조회값·처리 결과를 기준으로 요청값과 응답값 후보, 오류 시나리오 및 화면 반영 결과를 개인 실습으로 설계할 예정이다. 현재는 상세 시나리오와 실행 결과를 공개 문서에 수록하지 않았다.

실제 보험사의 API 엔드포인트, 스키마 또는 내부 구조를 재현한 문서가 아니다.

### 5. LLM QA — 개인 실습 예정

[LLM QA](./llm-qa/README.md)

보험 상담 LLM을 대상으로 정확성·근거성·일관성·거절 처리 및 개인정보 위험을 평가하는 개인 실습을 진행할 예정이다. 현재는 상세 평가 시나리오와 실행 결과를 공개 문서에 수록하지 않았다.

실제 직장에서 수행한 LLM QA 경험이 아니다.

## 작성 원칙

- 특정 보험사의 내부 명칭, 실제 고객정보, 실제 보험료 및 외부업체명은 공개하지 않는다.
- 실제 업무 경험과 포트폴리오용 개인 실습을 구분한다.
- 직접 확인하지 않은 개발 원인과 내부 시스템 구조는 추측하지 않는다.
- 정상 업무규칙, 실제 오류 및 수정 후 재검증 범위를 구분한다.
- 실제 수행한 테스트와 확인 범위까지만 작성한다.
- 면접에서 발생 조건과 자신의 역할을 설명하기 어려운 사례는 제외한다.
- 수치화되지 않은 개선 효과와 확인되지 않은 결과는 작성하지 않는다.
